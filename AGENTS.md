# AGENTS.md — обязательные инструкции для Codex и других coding agents

## Цель и источник истины

Ты работаешь над **Fog of Command**, pre-production PC-стратегией на Unreal Engine 5.x. Сначала прочитай `README.md`, `docs/ROADMAP.md`, `docs/ARCHITECTURE.md` и релевантные разделы `docs/Fog_of_Command_GDD_v0.1.md`. Самый узкий принятый Issue — источник истины по *объёму конкретной задачи*. GDD описывает долгосрочное видение, **не является требованием реализовать всё сразу**.

Если требования конфликтуют: безопасности данных/целостности состояния > критерии задачи > архитектурные инварианты > GDD. Укажи конфликт в PR, не меняй решение молча.

## Правила работы с Issues

1. Одна Issue (`FOC-###`) — один связанный PR; имя ветки `feat/foc-###-slug`, `fix/foc-###-slug` или `docs/foc-###-slug`.
2. Перед кодом перечисли минимальные файлы, которые изменишь, зависимости и способ проверки.
3. Реализуй только указанный scope. Новая технология, подсистема или платформа — отдельная Issue, если не требуется для принятой задачи.
4. Не мерджи PR самостоятельно и не пушь прямо в `main`, если владелец проекта явно не дал такое право. Сохраняй возможность ревью.
5. В PR укажи `Closes #N` (если номер уже известен), `FOC-###`, выполненные проверки и ограничения.
6. Если невозможно запустить Unreal на текущей машине, **не утверждай**, что UE-сборка или редактор были проверены. Приведи воспроизводимые команды/ручной smoke test для Windows.

## Архитектурные инварианты

- `WorldState` — авторитетное истинное состояние. `PerceivedWorldState` **отдельно для каждой стороны**; клиентский UI не имеет права читать истинные скрытые вражеские позиции.
- Каждый `UnitId` постоянен; переключение RTS↔ручной режим **не создаёт копий юнитов**, не меняет бесплатно боезапас, топливо, здоровье и сторону.
- Контакт разведки содержит **источник, время обнаружения, приблизительную позицию/неопределённость и статус**; старый контакт не показывается как текущий.
- Действия и приказы других подразделений **продолжаются**, пока игрок управляет одним объектом вручную.
- Любой расход/пополнение ресурсов проходит через проверяемые операции состояния; снабжение не создаёт ресурс из ничего.
- Не доверяй клиенту данные PvP. Будущее сетевое состояние — server-authoritative, без рассылки закрытых координат.
- Движковые Actors, HUD и эффекты — отображение; правила симуляции должны быть максимально отделены от представления для тестирования и будущих версий.

## Unreal/C++ правила

- **Не выдумывай точную версию UE.** Запиши проверенную версию в `docs/ENGINE_VERSION.md` при FOC-001, далее не обновляй без отдельного ADR/Issue.
- Используй штатные подсистемы Unreal и минимальное число сторонних плагинов. Не подключай World Partition/MassEntity/GAS «на всякий случай».
- Никаких сгенерированных `Binaries/`, `Intermediate/`, `Saved/`, `DerivedDataCache/`, секретов, неясных лицензий или гигантских демо-ассетов в Git.
- Unreal бинарные ассеты `.uasset`, `.umap` и др. — Git LFS; перед первым добавлением проверь `git lfs install`.
- Код: предсказуемые имена и явные владение/жизненный цикл, без тяжёлых операций в Tick без профилирования. Не создавать без нужды компоненты/Actors для каждой абстрактной стратегической сущности.
- Публичные API и сериализуемые форматы документировать, критические переходы покрывать Automation Tests или тестами чистых C++-модулей.
- Для логики обнаружения используй *игровые абстракции*. Не заявляй о документальной точности реальной военной техники.

## Definition of Done

- Выполнены критерии конкретной Issue; есть проверяемая демонстрация результата или тест.
- Проверены инварианты (UnitId, ресурсы, наблюдения, продолжение AI, если затрагиваются).
- Добавлены/обновлены тесты и документы для изменённого поведения.
- Не появились новые предупреждения компилятора, ошибки логов или запрещённые бинарные файлы (если это можно проверить).
- PR содержит фактические команды, результаты тестов и честные пометки `NOT RUN` для недоступных проверок.
- Показаны ограничения, риски, изменения баланса; не писать «готово», если критерии не выполнены.

## Приоритеты

Работать только с unblocked задачами `stage:0` → `stage:1` → `stage:2` → `stage:3`. `stage:4` и `stage:5` — **дальний backlog**, не начинать без решения владельца. Не создавать автоматические покупки, платные преимущества, аккаунты, MMO-серверы или интерфейсы монетизации в MVP.

## Когда остановиться и уточнить

Если требуются платные инструменты, публикация в магазин, новая лицензия, секреты, доступы, крупная архитектурная смена, изменение монетизации или существенное расширение scope — опиши варианты в PR/Issue и дождись решения владельца.
