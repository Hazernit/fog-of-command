# Публикация в GitHub и массовое создание Issues

В этом архиве подготовлен **локальный исходный набор**, не онлайн-репозиторий. Пока GitHub не подтвердил создание и пуш, никаких изменений на GitHub нет.

## Windows (рекомендуется на основном ПК)

1. Установить `Git`, `GitHub CLI (gh)` и `Python 3.11+`. Для будущих `.uasset` — `Git LFS`.
2. Один раз войти: `gh auth login`, затем `gh auth setup-git`.
3. Распаковать архив и открыть PowerShell в папке с `README.md`.
4. Проверить предпросмотр команд: `python scripts/publish_github.py --dry-run`.
5. Выполнить:

```powershell
python scripts/publish_github.py --owner Hazernit --repo fog-of-command --private
```

Команда создаст **приватный** репозиторий `Hazernit/fog-of-command`, запушит файлы в `main`, заведёт метки этапов/приоритетов, создаст эпики и задачи. Повторный запуск пропустит уже существующие Issues с теми же `FOC-###` идентификаторами.

**Важно:** если ты уже создал репозиторий через GitHub, пусть он будет **пустым**, без initial README/лицензии — иначе обычный push независимой истории не пройдёт; скрипт не применяет force.

## Mac

Те же команды через Terminal (если установлены `git`, `gh`, `python3`).

## Что скрипт не делает

- Не пушит секреты из .env, `Saved/`, `Binaries/`, `Intermediate/`.
- Не создаёт `.uproject` без Unreal Engine.
- Не назначает Codex автоматически исполнителем и не мерджит PR.
- Не включает платные сервисы, публичность или branch protection без отдельного решения.

## Безопасность и идемпотентность

Скрипт проверяет `gh auth`, права доступа, `origin` и `main`. Он не делает `git push --force`. Дубликаты задач предотвращаются проверкой ID в заголовке Issue; возможность штатно обновлять/закрывать задачи остаётся у владельца.

## Альтернативный путь

Создай **приватный пустой** репозиторий на https://github.com/new с названием `fog-of-command`; затем запусти ту же команду. В этой беседе подключённый GitHub умеет работать с файлами/Issues существующего репозитория, но не создавать новый репозиторий.
