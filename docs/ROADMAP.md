# Roadmap и этапы

**Backlog — намерения, а не обещания релизных сроков.** Этапы проходят последовательно по контрольным демонстрациям; поздние задачи не начинать параллельно без согласия владельца.

| Этап | Цель | Exit gate | Статус |
|---|---|---|---|
| **S0 — Foundation** | Проверить UE/Windows, создать C++ проект, инварианты и тестовую инфраструктуру | Clean checkout → открывается UE-проект → запускается минимальная карта, тесты и сохранение state | **В работе:** toolchain/smoke принят; FOC-002 следующий |
| **S1 — RTS core** | RTS-камера, выделение, приказы, 2 стороны и базовый бой | Игрок завершает простую операцию с ИИ | После S0 |
| **S2 — Recon & Fog** | Разница истинного и воспринимаемого мира, БПЛА и разведданные | Враг скрыт без обнаружения; разведка стареет; UI показывает источник/давность | После S1 |
| **S3 — Direct Control & Logistics** | Солдат/танк/дрон вручную, AI continues, пополнение и итог матча | Связный 20–30-минутный сценарий; ресурсы и Units не дублируются | После S2 |
| **S4 — Campaign spike** | 5–10 регионов, экономика, население, политика и связь с боем | Сохраняемая короткая кампания без дублирования войск | **Отложено** |
| **S5 — Online/platform experiments** | Доказать реализуемость PvP и выпусков | Измеренные прототипы и Go/No-Go по каждой платформе | **Отложено** |

## Вертикальный срез PC MVP

**Входит:** одна карта (~1.5×1.5 км — предварительно), две стороны, отделение пехоты, бронетехника, БПЛА, машина снабжения, 12–24 игровых единицы, `MOVE/HOLD/RECON/ENGAGE/RESUPPLY`, неопределённые контакты, переключение камеры и ручного контроля, 30-минутный стабильный сценарий, экран результата, сохранение.

**Не входит:** рождаемость, политика, глобальная карта, экономика на годы, массовый PvP, мультиплеер, монетизация, Roblox, мобильные клиенты, тысячи юнитов, фотореализм.

## Дисциплина проверки

- **После S0:** чистая сборка/запуск, версия UE и железо задокументированы.
- **После S1:** новая игра запускается и завершается без команд разработчика; вражеский ИИ действует объяснимо.
- **После S2:** ни одна сторона не получает истинные скрытые данные через боевой UI.
- **После S3:** один UnitId и один набор ресурсов до и после Possess, 30-минутный стабильный прогон, возможны победа и поражение.
- **После S4:** вход/выход из локального боя не создаёт ресурсы, не пропускает экономические тики, не теряет сохранения.
- **После S5:** серверная фильтрация данных/античит доказаны прототипом, отдельные оценки Steam/mobile/Roblox.

## Контроль времени

Первый PC-прототип: плановый порядок **3–6 месяцев** при работе одного разработчика ~15–20 ч/нед., но не обязательство. В конце каждого этапа сверять фактическую скорость и обновлять оценки. Не делить время по рекламным обещаниям ИИ-агентов.

## Плейтест и продуктовый критерий

20–30 внешних участников после S3; собираем: завершение обучения, понятность разведданных, использование ручного управления, желание повторить матч, FPS/ошибки. Если игровой цикл не интересен — меняем механику, а не начинаем S4.

## Решение по Windows baseline — 2026-10-26

После двух локальных успешных проверок **принята конфигурация UE 5.8.4 CL58902052 + VS2022 17.14.42 / MSVC 14.44.35229 + SDK 10.0.22621.0**. Это снимает блокировку на **FOC-002**. Детали: [ENGINE_VERSION.md](ENGINE_VERSION.md) и [отчёт](diagnostics/FOC-046-windows-smoke.md).

Независимый GPU stress **NOT RUN**. Не считать S0 завершённым, пока не выполнены FOC-002—FOC-007.
